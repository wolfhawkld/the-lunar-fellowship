# Lunar Lab Candidate · Living Memory Open Collaboration

> 状态：Candidate / 尚未激活
> 来源：[Lunar Session 01](../events/session-01-attention-living-memory-and-agency.md)
> 公开范围：Green
> 激活条件：至少两位成员主动投入、一位明确推动者，并能定义两周内的可展示结果

## 机会

当 AI 持续扩大信息与生成能力时，人的瓶颈越来越表现为注意力分配、上下文维护与长期记忆。`progressive-kg` 和 `living-memory` 已提供了一个值得共同验证的方向：用动态、三维、可成长的知识图谱，把阅读、思考、项目和人机协作形成的关系持续保存并重新唤起。

本候选 Lab 的目标不是立即重写现有项目，而是先判断：哪些问题适合共同解决，两个项目之间是什么关系，以及什么样的最小公开成果足以让更多贡献者理解和参与。

## 待验证的核心假设

1. 可成长的关系结构，比线性笔记或静态目录更有利于重新发现重要上下文。
2. 3D 表达只有在帮助选择、导航或形成新关系时才有价值；视觉复杂度本身不是目标。
3. 人与 Agent 可以围绕同一份 living memory 协作，但需要清晰区分事实、解释、假设、来源和演化历史。
4. 一个开放项目若能提供低门槛的可视化成果与明确贡献入口，更容易形成跨专业协作。

## 建议的首个两周结果

在项目正式激活后，从以下结果中选择一个，不默认全部完成：

- 一页项目地图：目标用户、核心场景、两个项目的关系、现有能力和关键缺口；
- 一个可演示的最小流程：输入一份阅读或项目材料，形成可增长关系，并能在后续问题中重新唤起；
- 一份开源启动包：README、架构草图、许可证候选、贡献说明和 3–5 个首批 Issue；
- 一项对比验证：用同一任务比较线性笔记、静态图谱和 living memory 对注意力恢复的帮助。

## 启动前必须确认

- **推动者与参与者**：谁负责收束范围，谁愿意在两周内实际投入；
- **项目关系**：`progressive-kg` 与 `living-memory` 是合并、依赖、互补还是独立实验；
- **权属与许可**：现有代码、设计、数据和名称是否有权公开，采用何种许可证；
- **验证场景**：服务哪个具体问题，什么结果算“比现状更好”；
- **公开边界**：只使用 Green 材料，不引入成员无权分享的公司或客户内容。

## 最小协作方式

- GitHub 保存公开代码、文档、Issue 与决策记录；
- Lunar Chat 捕捉信号、认领事项和快速反馈；
- 只有遇到需要共同推演的问题时才发起 Talk；
- 每轮只保留一个明确目标，并在约定回看点决定继续、调整或停止。

## 当前状态

本提案记录的是共同兴趣与可能方向，不代表项目已经启动，也不代表任何成员已经承诺投入。下一步需要在 Lunar Chat 中出现明确推动者，并完成启动前五项确认。
