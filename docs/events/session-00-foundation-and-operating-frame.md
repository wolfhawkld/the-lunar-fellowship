## 这次活动的性质

Session 00 不是围绕某个技术主题展开的内容型分享。它的主要作用是确定 The Lunar Fellowship 的基调，并在活动前后的讨论与整理中形成首版运行框架。

因此，它最重要的产出不是一组独立观点，而是一个可以持续容纳后续分享、讨论和协作项目的“共同容器”。当前 Lunar Hub 的主体结构正是这次交流前后形成的框架化表达。

## 五条以内摘要

1. The Lunar Fellowship 被定位为由个人自发连接、跨公司、跨专业的 AI 实践网络，不依赖固定汇报线或正式组织授权。
2. 社群采用 `Chat → Talk → Work → Chat` 的轻量协作闭环：日常发现信号，需要共同推演时同步交流，值得复用时再形成长期沉淀。
3. `Lunar Sessions` 用于有主题的交流，`Lunar Labs` 用于有明确问题、参与者、周期和产出的实践项目；二者不是组织层级。
4. 参与默认低压力：成员可以观察、回应、提问、分享或发起项目，不设置统一频率和最低贡献量。
5. 跨公司协作以安全边界为前提：成员只代表自己，默认不录制、不公开归因，也不分享无权分享的信息。

## 首版主体框架

### 1. 身份与方向

- 英文名：The Lunar Fellowship；
- 中文名：月曜同道会；
- 核心表达：独立个体，共享智能，协同行动；
- 连接逻辑：成员因共同判断与行动意愿形成“认知引力”，而不是因为属于同一组织。

### 2. 三种协作方式

- **Lunar Chat**：捕捉实践信号、问题、观察和快速回应；
- **Lunar Talk**：围绕一个具体问题建立共同理解；
- **Lunar Work**：沉淀可复用的认识、决定、行动与成果。

### 3. 两类协作载体

- **Lunar Sessions**：正式或经过策划的主题交流；
- **Lunar Labs**：具有明确问题、参与者、周期和产出的实践项目。

### 4. 参与方式

- 可以只观察或用表情回应；
- 可以提出一个具体问题或分享一次真实实践；
- 可以选择 Pass，不要求公开表达或开启摄像头；
- Talk 和 Lab 由真实兴趣触发，不把“持续开会”当作活跃目标。

### 5. 共同边界

- 每个人以个人身份参与，不默认代表所在公司；
- 带走启发，不带走未经允许的内容；
- Green 内容可以公开，Amber 内容限定范围，Red 内容不进入 Fellowship；
- 默认不录音、不录像、不自动转写，不建立未经同意的成员画像。

### 6. 轻量治理

- 角色服务于一次活动或一个周期，不形成固定等级；
- 低成本、可逆尝试可以直接试行；
- 涉及公开发布、成员边界或长期规则的事项需要留下提案和审阅窗口；
- 没有明确推动者的想法保留为候选，不视为行动承诺。
