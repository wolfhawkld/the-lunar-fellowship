# Lunar Chat 八人启动手册 v0.1

> 状态：Draft / 待试运行
> 适用阶段：建群后的前两至四周
> 核心：让贡献足够小、回应足够真实、升级足够自然。

## 1. 目标与投入假设

Lunar Chat 不是 Talk 和 Work 尚未成熟时的替代品，而是早期最重要的连接场域。

现阶段默认：

- 八位成员都有自己的工作和生活，空闲时间不稳定；
- 大家对 AI、个人成长和兴趣讨论有积极意愿，但不一定愿意承担固定任务；
- 一次有内容的三分钟分享，比维持表面热闹更有价值；
- 沉默可能代表忙、慢热或仍在观察，不代表缺乏认同。

成员没有每周最低投入。可以只阅读、用表情回应、偶尔提出问题，也可以主动推动 Talk 或 Lab。

## 2. 群里的四种最小动作

以下格式均为可选提示，不要求每条消息严格套模板：

### Signal / 信号

```text
[Signal] 我刚刚尝试或看到……
[Why] 我觉得值得注意，因为……
[Ask] 你们有没有类似经验，或会怎么看？
```

适合用三至五分钟分享一次实践、链接、产品变化或直觉。

### Ask / 问题

```text
[Ask] 我正在想一个具体问题：
……

不需要完整回答；一个案例、反例或关键词就有帮助。
```

### Echo / 回响

不需要另起完整观点，可以只回复：

```text
这让我联想到……
我遇到过一个相反的情况……
如果继续聊，我最想追问的是……
```

### Talk? / 是否值得同步聊

当文字讨论开始需要更多语境时，任何成员都可以问：

```text
[Talk?] 这个话题是否值得找 30–45 分钟同步聊？
感兴趣可以回一个 🌙，暂时不代表承诺参加。
```

## 3. 前两周的最小节奏

官方群运营动作每周最多两个，避免形成追赶压力。

### 建群当天

- 发布一次欢迎语和安全边界；
- 请成员用一个表情表示当前参与倾向：
  - 🌙 先认识和观察；
  - 🧪 愿意分享实践；
  - 🧩 手上有问题；
  - 🤝 希望寻找交流伙伴；
- 同时发布首次聚会时间投票。

### 第 1 至 3 天

召集人先发布一条真实但不必成熟的 Signal。重点是展示“半成品也可以说”，并在结尾留下一个足够具体、三分钟内能回答的问题。

提前邀请一至两位成员在不同时间发布自己的实践或问题，但不要求他们扮演正式分享者。

召集人的第一条内容可以很自然：

```text
我先抛一个最近在想、但还没有完整结论的问题。

[Signal] ……
[Why] ……
[Ask] 你们最近有没有类似体验？一句话、一个反例，或者只回个表情都可以。
```

### 第 4 至 7 天

- 不继续叠加新问题；
- 对已经出现的讨论给出一次三行以内的小结；
- 将相近兴趣连接起来，例如：“A 和 B 都提到了 Agent 评估，如果你们愿意可以在这里继续聊”；
- 周末只保留自然分享，不安排规定动作。

### 第 2 周

- 发布一个从第一周内容自然长出来的问题；
- 如果首次聚会已经举行，用五条以内摘要回到 Chat；
- 如果某个话题获得至少三位成员明确兴趣，再询问是否发起一次 30 至 45 分钟 Talk；
- 没有自然形成 Talk 也完全正常。

## 4. 召集人的“园丁动作”

早期召集人的任务不是持续生产内容，而是帮助成员之间形成连接：

- 自己先分享具体、真实、允许不完美的内容；
- 对成员的重要分享至少给一次有内容的回应；
- 有机会时把问题递给可能有经验的成员，但私下征得同意后再点名；
- 一个问题回应较少时，用投票或更具体的小问题降低门槛，不反复 `@所有人`；
- 一段讨论在 24 至 48 小时后自然结束时，简单总结或明确暂时搁置；
- 不要求所有人跟上所有消息，不用消息数量公开比较成员活跃度；
- 不让自己永远成为唯一的提问者和回应者，逐步把空间让给成员。

## 5. 什么时候从 Chat 升级

### 升级到 Talk

同时满足以下条件：

- 有一个明确问题，而不是泛泛“聊 AI”；
- 至少三位成员表达兴趣；
- 有一位召集人；
- 30 至 60 分钟有可能形成新的理解或下一步。

Talk 可以只有部分成员参加，结束后只需向 Chat 带回五条以内摘要。

### 沉淀到 Work

出现以下任一内容时，由召集人或记录者整理：

- 可复用的方法、清单或案例；
- 形成的决定及负责人；
- 值得后续验证的假设；
- Talk 或 Lab 的简要结果。

普通成员不承担“每次发言后还要写文档”的义务。一次沉淀控制在结论、未决问题、下一步、推动者四项以内。

### 升级到 Lab

只有当至少两位成员主动愿意投入，并能定义两周内的小产出时才进入 Lab。兴趣讨论本身也可以是完整结果，不必都转化为项目。

## 6. 建议的时间预算

这不是考核，只用于防止机制变重：

| 参与方式 | 单次参考时间 |
|---|---:|
| 阅读、表情回应 | 10 秒至 1 分钟 |
| 一句话回答 | 1 至 3 分钟 |
| 一条 Signal 或 Ask | 3 至 5 分钟 |
| 有内容的回应 | 5 至 10 分钟 |
| 帮助整理一次讨论 | 10 至 15 分钟 |
| 一次可选 Talk | 30 至 60 分钟 |

召集人首周用于建群、回应、整理和活动协调的总投入，建议尽量控制在 60 至 90 分钟以内，不把社群运营变成第二份工作。

## 7. 两周后的健康信号

不统计打卡率，观察：

- 大多数成员至少使用过一种低压力参与方式；
- 群里出现了成员直接回应成员，而不只是回应发起人；
- 至少出现两三个真实实践、问题或有意义的链接说明；
- 有一个话题获得多位成员继续交流的兴趣；
- 重要内容得到一次简短整理；
- 成员没有明显的追消息、必须输出或被迫承诺的压力。

只要成员愿意继续打开群、愿意偶尔说一句真实的话，并逐渐记住彼此擅长和关心什么，第一阶段就已经有效。
